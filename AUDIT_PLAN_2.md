# План исправлений по итогам второго аудита

Второй аудит: код, механика игры, данные, синхронизация, производительность, UI/UX.
Пункты первого аудита (`AUDIT_PLAN.md`, этапы 1–11) закрыты и здесь не повторяются.

Обозначения пунктов — как в отчёте аудита: **H** — High, **M** — Medium, **L** — Low.
Critical-проблем не найдено.

**Статус:** план составлен, работа не начата.

## Порядок работы на каждом этапе

1. Работа в отдельной ветке, `main` не трогаем.
2. Только правки текущего этапа — ничего сверх.
3. Сборка и тесты (`xcodebuild build` / `test`) — на Mac: в облачной среде Xcode нет.
4. Сводка: что изменено и почему, затронутые файлы, что проверить в симуляторе.
5. Коммит — только после одобрения.
6. **`push` — только по отдельной явной команде.**

Этапы, отмеченные «нужно решение», не начинаются, пока в таблице «Открытые решения» нет ответа.

## Этап 1. Быстрые исправления механики (решений не требует)

- [ ] **H1** — экзамен всегда собирается из одних и тех же вопросов: `prefix(count)` берётся до перемешивания, поэтому «Пересдать» даёт тот же набор. Перемешивать до отбора; тест на разные наборы.
  `ExamUseCase.swift:162–166`
- [ ] **H5** — неверный индекс правильного ответа «зажимается» до последнего варианта, и правильным становится другой ответ. Такой вопрос отбрасывать; тест на путь загрузки, а не только на валидатор.
  `RemoteQuestion.swift:69, 83`
- [ ] **M3** — пауза в течение 1,5 с после ответа: автопереход не отменяется, таймер следующего вопроса идёт под экраном паузы. Отменять переход при паузе или блокировать кнопку на время перехода; тест.
  `ExamViewModel.swift:229–236, 280–286`, `ExamView.swift:198–206`
- [ ] **M2** — «Сбросить достижения» обнуляет `totalQuestionsStudied`, но не `correctAnswers`: у гостя точность больше 100%. Сброс достижений не должен трогать статистику ответов.
  `StatsManager.swift:215–224`, `ProfileStatsSectionView.swift:83–84`
- [ ] **L1** — досрочное завершение повторения ошибок: процент считается с неотвеченными вопросами.
  `QuizViewModel.swift:426–430`
- [ ] **L2** — `QuizResult.isNewRecord` сравнивает с 0.8 вместо 80 (не используется — удалить).
  `Question.swift:83`
- [ ] **L3** — «мемоизация» в `@Observable` меняет состояние внутри геттера. Убрать.
  `QuizViewModel.swift:45–76`
- [ ] **L4** — NaN в `averageScore`, если первый экзамен завершён без ответов; статистика молча не сохраняется.
  `ExamMode.swift:214`
- [ ] Повторяющаяся строка генерации рекомендаций.
  `AdaptiveLearningEngine.swift:82–83`

## Этап 6. Модель прогресса и синхронизация — *нужны решения №1, №2, №5*

Самый большой и рискованный этап; делится на шаги после принятия решений.

- [ ] **H3** — в iCloud уходит только `ProfileProgress`; не синхронизируются ошибки, расписание повторений, серия дней, ежедневная цель, пройденные вопросы банка, достижения, `perfectScores`, `totalQuizzesCompleted`. При входе `totalQuizzesCompleted` обрезается до длины истории (≤ 20); история дублируется (новые `UUID` при каждом запуске); серия и средний балл при слиянии только растут (`max`).
  `ProfileProgressBuilder.swift:66–76`, `ProfileMergeService.swift:70–88, 155–165`, `StatsManager.swift:227–280`, `ProfileManager.swift:271–288`
- [ ] **M10** (часть) — две модели статистики (`UserStats` и `ProfileProgress`) с синхронизацией в обе стороны → одна модель прогресса, синхронизируется полный снимок с правилами слияния для каждого поля.
- [ ] **M9** — рекомендации, `masteryLevel`, `quizHistory`, `ProfilePreferences` считаются и синхронизируются, но не показываются; рекомендации хранятся готовым текстом с id темы. Удалить или вывести (решение №5).
  `AdaptiveLearningEngine.swift:285–329`, `UserProfile.swift`
- [ ] **M13** — нет проверки `getCredentialState` (отзыв доступа Apple ID не обрабатывается); данные лежат в приватной базе iCloud-аккаунта, вход через Apple для синхронизации не нужен (решение №1).
